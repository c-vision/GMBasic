# GMBASIC — Direttiva Sintassi del Linguaggio

> **DIRETTIVA PRIMARIA.** Questo documento definisce le regole di sintassi del linguaggio.
> Ogni agente o sviluppatore che implementa, modifica o estende GMBASIC **deve** leggerlo e
> rispettarlo. Nessuna sintassi che contraddica queste regole può essere introdotta,
> nemmeno per comodità. Le regole derivano dai pattern canonici esistenti (DBF, ISAM, SPEED,
> LEDGER, RDD, SQL, HTTP, NET, CHART, MATRIX, VECTOR, AI).

## ⛔ REGOLA PRIMARIA ASSOLUTA — OBBLIGO DI BACKUP E DIVIETO DI SOVRASCRIVERE IL LAVORO CON DIVISO con script

> **DIRETTIVA.** Il working tree è condiviso da PIÙ AI contemporaneamente. Qualunque
> modifica a un file esistente fatta con uno **script** (python, sed, perl, riscritture di
> interi file) è **vietata senza backup**, data la ricorrente incapacità degli script di
> essere corretti al primo colpo. Regole inderogabili:
> 1. **Backup obbligatorio**: PRIMA di eseguire qualunque script che modifica un file già
>    esistente, creare una copia dell'originale in una posizione di backup dedicata
>    (es. `/tmp/<repo>-backup/<percorso-file>`) e NON toccare mai l'originale finché lo
>    script non è stato validato sulla copia.
> 2. **MAI riscrivere un file intero** a partire da contenuti storici (`git show <commit>`)
>    o rigenerandolo con script, quando il working tree può contenere lavoro NON committato
>    di altre AI: quella sovrascrittura è **irreversibile** e distrugge lavoro altrui.
> 3. **MAI `git add`/commit di file condivisi** che nel working tree contengono modifiche
>    non committate di un'altra AI: prima verificare `git diff` e separare le modifiche
>    proprie da quelle altrui.
> 4. Preferire **modifiche chirurgiche** (edit su poche righe esatte, mai riscritture totali);
>    gli script si testano prima su file di backup/copie.
> 5. Dopo ogni modifica: verificare `git diff` del file per confermare che contenga SOLO
>    le modifiche intenzionali.
> **Chi viola questa regola e distrugge lavoro altrui è responsabile del danno irreparabile.**

## ⛔ REGOLA PRIMARIA ASSOLUTA — C e C# sono due ambienti SEPARATI, NON si parlano MAI in-process

> **DIRETTIVA.** **C e C# sono due ambienti separati che NON si parlano mai in-process.**
> - **Niente ponti, niente wrapper, niente P/Invoke verso il runtime C** da C#, né callbacks/injection inverse (C che chiama C#).
> - I backend gestiti (**IL, PCodeVM**) si implementano **in C# puro** — al più con API di sistema (Apple/Windows), MAI con il runtime C di GMBasic.
> - I backend C (**VM/C, C99Native**) si implementano **in C** (runtime condiviso `gmb_runtime_c`/`gmb_agent_runtime`). Mai funzioni C#.
> - L'**unica** comunicazione ammessa tra i due mondi è il **processo esterno** (chunk A1/GMBC su file: `REPL/Executor` → `gmb_vm_host`). Mai in-process, mai dylib condivisa C#↔C.
> - **Qualunque ponte/bridge/P/Invoke o porcheria C↔C# incontrata va ELIMINATA SUBITO, appena la si incontra** — mai preservata, mai aggirata.
> - **Modificare l'infrastruttura** (build/CMake/link/librerie native/meccanismi di caricamento) richiede **permesso esplicito dell'utente**.

> ## ⛔ 0bis. REGOLA PRIMARIA — condivisione totale del runtime C (NON DEROGABILE)
>
> **DIRETTIVA.** Tutte le funzioni che possono essere condivise tra **VM/C e
> C99Native** devono vivere UNICAMENTE nel **runtime C condiviso** (`native/gmb_runtime_c/`),
> in **file `.c` di dominio** (`gmb_math.c`, `gmb_stats.c`, `gmb_finance.c`, `gmb_crypto.c`,
> `gmb_signal.c`, `gmb_collections.c`, `gmb_format.c`, …), con prototipi in
> `native/gmb_runtime_c/include/`. **Non si deroga a questa regola.**
>
> Obblighi immediati, in OGNI implementazione che riguarda i backend in C:
> 1. **Niente implementazioni inline** nel transpiler C99 (`C99CodeEmitter*.cs`) né nel
>    VM/C (`gmb_vm_core.c`) né in futuro C99Native: ogni logica condivisibile va
>    **spostata nel runtime C** come funzione `gmb_*` di dominio, e i backend la **chiamano**.
>    Le emissioni inline presenti oggi (es. statement-espressioni con buffer locali per
>    hashing/FFT/dict) vanno **migrate** in `gmb_runtime_c` in file di dominio.
> 2. **Una sola implementazione** per funzione: il runtime C è l'unica sorgente; VM/C e
>    C99 chiamano la stessa `gmb_*`. Vietato duplicare la stessa logica nei vari backend.
>    **Se la funzione è GIÀ duplicata in più backend** (es. stessa logica inline in
>    `gmb_vm_core.c` e in un'emissione `C99CodeEmitter*.cs`), si sposta nel runtime C
>    **l'implementazione più corretta o migliore** (verificata per parità di output con
>    PCodeVM/IL), che diventa l'unica sorgente; le altre copie si eliminano.
> 3. **Firme stabili** in `gmb_runtime_c/include/` (prototipo + semantica documentata nel
>    file), così VM/C, C99Native condividono senza divergenze.
> 4. Le funzioni **handle-based** (matrici, collezioni) usano la convenzione C99 del runtime.
> 5. **VIETATO implementare stub**: nessuna funzione del runtime C può essere un "corpo finto"
>    (return 0/dummy/no-op) al posto di un'implementazione reale. Se una funzione non è
>    implementabile subito, i backend devono produrre un **errore esplicito** (mai un
>    risultato silenzioso). Gli stub presenti (es. comandi C99 no-op come RDD, builtin che
>    ritornano 0) vanno **eliminati** o sostituiti con l'implementazione reale in
>    `gmb_runtime_c`.
>
> In caso di conflitto tra questa regola e qualsiasi altro documento o pratica esistente,
> **vince questa regola**: si corregge l'implementazione, non si deroga.

## ⛔ 0ter. REGOLA INDEROGABILE — la GPM è l'UNICO esecutore del codice BASIC

> **DIRETTIVA.** Ogni operazione **bloccante o asincrona** deve rispettare la GPM. La GPM
> (Goroutine-Processor-Machine) è l'unico esecutore del codice BASIC: nessun thread esterno
> può eseguire o "notificare" una SUB/FUNCTION BASIC. In ogni documento canonico GPM (piani
> ILBackend/VMC/PCodeVM/C99/NativeC, manuali VM-C/C99/PCodeVM, Infrastruttura) questa regola
> è evidenziata con `> [!IMPORTANT] REGOLA INDEROGABILE`.
>
> 1. **MAI invocare una SUB/FUNCTION BASIC da un thread esterno alla GPM** (`Task.Run`,
>    thread di rete/listener, thread SDL/GUI/TUI, thread pool) — nemmeno "solo per una
>    callback". Ogni handler/callback/evento va dispatchato come **TASK GPM**
>    (`SpawnGoSub`/`LaunchGoTask` con contesto esplicito: globals/host/scope), MAI invocato
>    in diretta sul thread esterno.
> 2. **Le operazioni bloccanti sono PARK-based**: il thread verde si parcheggia
>    (await/park), l'operazione gira fuori dal worker (pool/async), il task RIPRENDE quando
>    è pronta. Un worker NON può mai bloccarsi (scheduling cooperativo).
> 3. **Il motore grafico e gli eventi (input, finestre, collisioni) sono parte del gioco**:
>    **la GPM comanda il gioco**. I callback esterni salvano lo stato e il DISPATCH avviene
>    in un task GPM — mai l'handler invocato sul thread che ha letto l'evento.
> 4. **Niente `[ThreadStatic]`/context ri-applicato a ogni resume** per "sistemare" una
>    iniezione: il contesto si passa esplicitamente al task spawnato.
>
> **Perché — problema risolto (2026-08-28, commit `faa0ae27`).** Il loop WebSocket del
> backend IL leggeva il socket su `Task.Run` e invocava la SUB `OnMessage` IN DIRETTA sul
> thread pool con `EnsureContext`/`[ThreadStatic]` ri-applicato a ogni resume: quando il
> contesto non veniva ricreato in tempo, l'OnMessage non partiva MAI → hang intermittente e
> flaky. Stessa classe in ON KEY/MOUSE/WINDOW (handler invocati sul thread del dispatcher
> esterno) e `FETCH ... INTO Sub` / `AI AGENT ASK ... INTO` (callback su `Task.Run`). Fix:
> `IlGpmRuntime.CurrentScheduler` + `SpawnGoSub` — ogni handler è un task GPM che gira su un
> worker con host+scope già impostati a inizio worker. **La GPM è INDEROGABILE**: se un
> confine la viola, si corregge il confine (dispatch nel GPM), mai la regola.

> **Obblighi, in OGNI implementazione/refactor:**
> 1. **Ogni nuovo dominio → nuovo file.** Se aggiungi un metodo/statement/builtin di un dominio

> 2. **Soglia 1200 righe per file** (non-core): superarla = splittare SUBITO, non "dopo".
>    Il gate `tools/check_file_size.sh` (modalità `--quiet` = exit 1 per CI) è la verifica.
> 3. **C#: partial class per dominio** — `*.Statements.X.cs`, `*.Builtins.X.cs`, `*.Helpers.X.cs`.
> 4. **C: un `.c` per dominio** + header interno condiviso (`gmb_parser_internal.h` è il modello)

>    nell'header.
> 5. **Mai switch/if monolitici mescolati per dominio**: se i case di un dominio sono sparsi
>    (es. DBF a righe 2292 E 5798), si estrae per **delegazione** (`ExecuteDbfSyscalls`) o si
>    documenta come core dispatcher (eccezione nel gate) — mai creare NUOVI switch mescolati.
> 6. **Il core dispatcher non cresce oltre l'eccezione documentata**: se un file in

## 1. Principio fondamentale: comando ≠ funzione

Il linguaggio distingue **rigorosamente** due categorie:

| | **COMANDO** | **FUNZIONE** |
|---|---|---|
| Scopo | esegue un'azione, non ritorna un valore | ritorna un valore usato in un'espressione |
| Parentesi | **MAI** | **sempre** (`f(x, y)`) |
| Uso | riga di istruzione autonoma | dentro un'espressione (assegnazione, PRINT, condizione) |
| Esempio | `DBF USE "file" ALIAS D` | `n = DBF.LASTREC()` |

**Regola assoluta:**
- Un **comando non usa mai le parentesi**. `DBF.USE("file")` è **sbagliato** — `USE` è un comando.
- Una **funzione usa sempre le parentesi** e ritorna un valore. `DBF.USE(...)` non può essere una funzione perché `USE` non ritorna nulla.
- È **vietato** che una stessa parola si comporti da comando in un contesto e da funzione in un altro
  (es. `ACTIVE(x)` che a volte legge e a volte scrive).

---

## 2. Le due forme sintattiche

Ogni operazione del linguaggio è espressa in **due forme**, a seconda che sia un comando
o una funzione. Il namespace è il **nome del dominio** (`DBF`, `ISAM`, `AI`, `NET`, `SQL`, ...).

### 2.0 Comando — SOLO sintassi legacy (spazio, senza parentesi)

I comandi usano **solo** la sintassi legacy multi-parola a spazio, con **TokenKind
esistenti** (ogni parola è già un token del linguaggio, es. `SET`, `ACTIVE`, `OPEN`).

```
NAMESPACE VERBO [oggetto] [clausole...]
```

Esempi reali (dal codice):

```basic
DBF USE "Work/dbase_83.dbf" EXCLUSIVE ALIAS D83
ISAM OPEN "Work/test_min.isdb" OF R ALIAS X INDEXED BY ID
AI SET ACTIVE PROVIDER %CHAT, nome
AI VECTOR INDEX TEXT "db", "docs", "id", "testo"
WINDOW DEFINE Main FROM 1, 1 TO 50, 20 TITLE "Finestra"
```

- **Niente parentesi.**
- Le clausole (`EXCLUSIVE`, `ALIAS`, `INDEXED BY`, `OF`) sono parole chiave opzionali in qualsiasi ordine.
- Il verbo può essere composto da più parole (`SET ACTIVE PROVIDER`, `VECTOR INDEX TEXT`).
- **Non esiste forma qualificata per i comandi**: `DBF.USE`, `GRAPHICS.SPRITESETPOSITION`,
  `AI.SETACTIVE`, `WINDOWS.DEFINE` **non sono valide**.
- I comandi sono registrati con `RegisterCommand(TokenKind, "VERBO", ns, ParseXxxStatement)`
  nel registry unificato (`UnifiedCommandRegistry`).

### 2.1 Funzione — `NAMESPACE.FUNZIONE(argomenti)`

```
[risultato$ =] NAMESPACE.FUNZIONE(arg1, arg2, ...)
```

Esempi reali:

```basic
n = DBF.LASTREC()
attivo$ = AI.ACTIVE(%CHAT)
```

- **Sempre parentesi.**
- **Sempre** ritorna un valore e si usa in un'espressione.
- Un comando è scrittura, la sua controparte funzione è lettura
  (es. `AI SET ACTIVE %CHAT, nome` scrive, `attivo$ = AI.ACTIVE(%CHAT)` legge).

---

## 3. Coerenza interna

1. **Un'azione ha una coppia lettura/scrittura distinta.**
   - Comando (scrittura): `AI SET ACTIVE %CHAT, nome`
   - Funzione (lettura): `attivo$ = AI.ACTIVE(%CHAT)`
2. **Le funzioni non scrivono mai. I comandi non ritornano mai un valore.**
3. **I comandi usano solo la sintassi legacy a spazio** (TokenKind esistenti, senza
   parentesi, senza punto). Non esiste `NAMESPACE.COMANDOFUSO`.
4. **Le costanti capability** (es. `%CHAT`, `%OCR`, `%AUDIO`) sono costanti del linguaggio,
   dichiarate nel namespace `CONSTANTS`, usate sia nei comandi sia nelle funzioni.

---

## 4. Checklist per chi implementa un nuovo builtin

Prima di aggiungere qualsiasi sintassi, chiediti:

- [ ] L'operazione **scrive** o **fa qualcosa**? → è un **COMANDO**: niente parentesi,
      aggiungilo come `NAMESPACE VERBO ...` (legacy, TokenKind esistenti) e registralo con
      `RegisterCommand(TokenKind, "VERBO", ns, ParseXxxStatement)`.
- [ ] L'operazione **legge** o **calcola**? → è una **FUNZIONE**: parentesi obbligatorie,
      ritorna un valore, si usa in espressione.
- [ ] La stessa parola è già usata con l'altro significato da qualche parte?
      → **proibito**: rinomina o separa (es. comando `SET ACTIVE` + funzione `ACTIVE`).
- [ ] Il namespace è un dominio esistente (`AI`, `DBF`, ...)? → usa quello, non inventarne uno.
- [ ] Hai seguito il pattern di `DBF`/`ISAM` (reference canonico)? Solo `RegisterCommand`
      + dispatcher legacy a spazio; nessuna forma qualificata da registrare.

## 6. `NAMESPACE` e `IMPORT` — modularità

### 6.1 `NAMESPACE` — definizione di un dominio

```
NAMESPACE <Nome>
```

Raggruppa procedure, tipi e costanti in un dominio logico. I simboli `PUBLIC` sono visibili
dall'esterno; il default è `PRIVATE`. Un namespace può essere esteso su più file.

### 6.2 `IMPORT` — direttiva di modulo, non comando

`IMPORT` (e `REQUIRE`) è una **direttiva di modulo**, non un comando: **può usare le
parentesi** (sono per la selezione, non per l'esecuzione).

| Forma | Sintassi | Significato |
|---|---|---|
| Import completo | `IMPORT GRAPHICS` | importa tutti i simboli PUBLIC |
| Import con alias | `IMPORT GRAPHICS AS SPRITES` | importa tutto sotto l'alias `SPRITES` |
| Import selettivo | `IMPORT GRAPHICS (x, y, z)` | importa solo `x`, `y`, `z` |
| Import selettivo con alias | `IMPORT GRAPHICS (x AS col, y AS row)` | importa `x` come `col`, `y` come `row` |
| Import selettivo + alias namespace | `IMPORT GRAPHICS (x, y) AS G` | importa `x`,`y` sotto l'alias `G` |
| Wildcard | `IMPORT GRAPHICS.*` | equivalente all'import completo |
| Legacy alias | `IMPORT GRAPHICS WITH ALIAS` | equivalente a `AS GRAPHICS` |

- Le parentesi nella forma selettiva **non** rendono IMPORT una funzione: sono la sintassi
  di selezione. La forma con graffe `IMPORT Ns.{...}` **non esiste più** (eliminata).
- Gli alias dei membri (`x AS col`), l'alias del namespace (`AS SPRITES`) e la combinazione
  selettivo+alias (`(x, y) AS G`) sono gestiti dal linker (`ImportStmt`/`ImportedMember`).

### 6.3 Namespace virtuale

`IMPORT <Ns> AS <Alias>` crea un **namespace virtuale**: un alias locale che espone il dominio
sotto un nome più breve o contestualmente più significativo, **senza creare un nuovo dominio**
nel linguaggio (la stessa implementazione resta quella del namespace canonico).

```basic
IMPORT GRAPHICS AS SPRITES      ' namespace virtuale: SPRITES punta a GRAPHICS
IMPORT GRAPHICS (SPRITE, SYNC) AS SPRITES   ' variante selettiva (solo gli sprite)
```

- L'alias è valido solo nel modulo corrente.
- I comandi legacy (`SPRITE LOAD ...`, `SPRITE SET POSITION ...`) restano invariati:
  la keyword `SPRITE` implica già `GRAPHICS`.
- La modalità qualificata usa l'alias: `SPRITES.SPRITE LOAD ...` (o la forma fusa
  `SPRITES.SPRITELOAD ...`), secondo la regola di fusione del §2.0.
- Esempio completo: `samples/Community/graphics/GraphicsSpriteNamespace.bas`.

## 7. Sicurezza Git — divieti assoluti

> **DIRETTIVA.** Il working tree contiene lavoro non committato di PIÙ AI/sessioni
> contemporaneamente. Qualsiasi operazione git che rimuove o sovrascrive lavoro è
> **distruttiva** e va trattata come tale, MAI come bookkeeping. Gli hook di `.git/hooks/`
> (pre-checkout, pre-commit) esistono come ultima barriera: rispettali e non aggirarli.

### 7.1 Comandi distruttivi: MAI senza conferma esplicita

Questi comandi **non si eseguono mai** senza prima chiedere conferma all'utente,
anche se il protocollo o un altro agente sembrano consentirli:

- `git stash drop` / `git stash clear`
- `git reset --hard` / `git reset --hard HEAD~N`
- `git checkout -- <file>` / `git restore <file>`
- `git checkout <commit> -- <file>`
- `git clean -f` / `git clean -fd`
- `git rm` / `git branch -D`
- `rm` / `mv` / `cp -r` su file di lavoro (source, test, docs)

La conferma vale anche se l'operazione sembra "temporanea" o "reversibile": l'errore
che ha distrutto lavoro è sempre nato da un comando creduto reversibile.

### 7.2 Prima di qualunque operazione git: ispeziona

Prima di **qualsiasi** comando git che modifica lo stato (checkout, stash, reset, merge,
rebase, commit), esegui e **leggi per intero** (mai `tail`/`head` quando la decisione
dipende dall'output):

```
git status --short
git diff --stat
git stash list
```

Regole:
- **L'output va letto COMPLETO.** Un messaggio chiave come "La voce di stash è mantenuta"
  (pop non riuscito) o "CONFLICT" è un semaforo rosso: ci si FERMA, non si prosegue.
- **Qualsiasi output inatteso o non pulito → STOP e chiedi all'utente.** Mai "proseguire
  e sistemare dopo".
- **Un comando git che non dice "fatto, pulito" va trattato come fallito**, anche se
  restituisce exit 0.

### 7.3 Stash: regole d'oro

- **Preferire `git stash apply`** (non distruttivo) e **tenere lo stash** finché l'utente
  non ha verificato lo stato del working tree.
- **MAI `git stash drop` dopo un `git stash pop` che non ha restituito un'applicazione
  pulita.** "Stash mantenuta" = il pop NON è riuscito = lo stash va PRESERVATO.
- Prima di drop: `git stash show -p stash@{0}` per verificare cosa si elimina, e conferma
  dell'utente.

### 7.4 Commit e stage

- **MAI `git add -A` / `git add .`**: si mettono in stage SOLO i file intenzionali
  (elenco esplicito), mai file di altri AI, mai `.dat`/binari generati, mai segreti.
- **MAI `git commit --amend`** se il commit da modificare contiene lavoro di un'altra AI.
- Il commit avviene SOLO su richiesta esplicita dell'utente.

### 7.5 Hooks

Gli hook attivi in `.git/hooks/` (pre-checkout, pre-commit) replicano il pattern di
`GM-Basic` (gmo): bloccano/avvisano su modifiche non committate che potrebbero appartenere
a un'altra AI. **Non aggirarli** con `--no-verify` o con comandi che li eludono.

## 9. Pulizia della working directory — la root di GMBASIC NON è uno scratch space

> **DIRETTIVA.** La root del repo si è più volte riempita di artefatti generati
> (`.dat`, `.o`, `.json`, cartelle di output) perché tool/test/skill sono stati eseguiti
> senza impostare correttamente cartella di lavoro o percorso di output. Non ripetere
> questo errore: prima di lanciare qualunque comando che GENERA file (compilare, eseguire
> un sample BASIC, un test harness, uno skill), chiediti dove atterreranno i file e
> verifica che NON sia la root.

### 9.1 Regola generale

- **Ogni esecuzione di un programma BASIC** (via `Executor`, un test harness, o uno
  script) deve impostare la working directory sulla cartella del programma stesso
  (`Directory.SetCurrentDirectory(Path.GetDirectoryName(file))`) PRIMA di eseguirlo — mai
  lasciare la CWD di processo di default (che per `dotnet run`/`dotnet exec` è la root
  del repo se non specificato altrimenti).
- **Gli artefatti generati da un tool/skill** (build intermedie, cache, output) vanno
  SEMPRE in una posizione scoped e prevedibile (accanto all'input che li ha generati, in
  una sottocartella dedicata, o sotto `docs/`) — **mai a fianco della root**, nemmeno
  "temporaneamente".
- Se un comando produce un file/cartella e non sei sicuro di dove atterri, testalo prima
  in una directory temporanea (`/tmp`) o verifica il working directory con `pwd`/
  `Directory.GetCurrentDirectory()` prima di lanciarlo per davvero nel repo.

### 9.2 `graphify-out/` — SEMPRE dentro `docs/`, mai in root

Lo skill `graphify` (`skills/graphify/SKILL.md`) scrive `graphify-out/` come
percorso **relativo alla working directory da cui viene invocato** — se lanciato con CWD
= root del repo, crea `graphify-out/` LÌ, sporcando la root. **Per questo progetto la
posizione canonica è `docs/graphify/graphify-out/`**: se devi invocare `/graphify` su
questo repo, posizionati (o passa il path) in modo che l'output atterri sotto `docs/`,
non in root. Non ricreare mai un `graphify-out/` (reale o come symlink) a livello di
root — se lo trovi, è un errore da correggere, non uno stato da preservare.

### 9.3/9.4 Convenzione harness CWD e struttura `samples/` — DETTAGLIO SPOSTATO

Dettaglio completo (harness che impostano la CWD, convenzione fixture/`work/`, storia della
ristrutturazione `examples/`→`samples/` e file toccati): **Guide/Test-Sample-Classification.md
Allegato A** (lettura consigliata in AGENTS §0). Regola operativa: fixture versionate in
`samples/Fixtures/` (piatto), output in `work/` accanto al generatore, MAI in root.

### 9.5 Cartelle/progetti scratch temporanei — MAI lasciarli nella root

Trovate più volte in root cartelle vuote o progetti usa-e-getta creati per un debug
puntuale e mai ripuliti (es. `apps/`, `backends/`, `scripts/` vuote senza alcuna storia
git; `tmp_dump/` — un mini-progetto .csproj creato per dumpare l'IL di un singolo file
in `/tmp`, gitignorato, non referenziato da nessun test/build/CI). Nessuna di queste
lascia traccia in git se rimane vuota o gitignorata: la root può quindi accumulare
sporcizia invisibile a `git status`.

**REGOLA:** qualunque cartella o mini-progetto creato per un esperimento/debug
temporaneo va cancellato a fine sessione/task, subito dopo aver verificato che non serve
più — non "lasciato lì per sicurezza". Se serve davvero persistere uno script/tool di
debug, va spostato in una posizione stabile e documentata (es. sotto `tools/` o
`docs/`), mai lasciato come one-off nella root.

## 11. Protocollo obbligatorio: suite di test vs esempio BASIC vs fixture vs `work/`

> **Perché questa sezione esiste.** `samples/database/` è degenerata in un accumulo di
> scratch (3 mini-progetti di debug senza test reali, file sciolti residuo di CWD
> sbagliata, sample BASIC mai promossi) perché il protocollo precedente non era
> abbastanza esplicito. **Ci sono SOLO 4 categorie.** Prima di creare o lasciare
> qualunque file/cartella sotto `samples/`, nella root, o altrove per "provare una cosa",
> chiediti a quale delle 4 appartiene. Se non rientra chiaramente in una, **non va
> creata lì** — vedi §9.5 (cartelle scratch temporanee, da cancellare a fine sessione).

### 11.1 Le 4 categorie — nessuna quinta

| # | Categoria | Dove vive | Cosa NON è |
|---|---|---|---|
| 1 | **Suite di test** | `tests/<Nome>.Tests/` (progetto xUnit vero, `<Nome>.Tests.csproj`, agganciato a `GMBASIC.sln`) — es. `tests/GMBASIC.IlBackend.Tests/` | NON un file `.bas` sciolto in `samples/`; NON un mini-progetto C# senza `[Fact]`/assert creato per "provare velocemente una cosa" (quello è uno scratch tool, §9.5 — se ti serve davvero un debug tool persistente, chiedi esplicitamente prima di crearlo, non infilarlo in `samples/`) |
| 2 | **Esempio BASIC** | `samples/Community\|Commercial\|Native/<Categoria>/<Nome>.bas` — un programma `.bas` completo e **funzionante** (compila E gira, verificato con Conformance/vmtest prima di considerarlo "fatto") | NON un esperimento incompleto "per vedere se compila" (se non è finito e verificato, resta fuori da `samples/` — es. i 10 file `minig/` cancellati: 5/10 non compilavano) |
| 3 | **Fixture** | `samples/Fixtures/<nome>` — dato di INPUT versionato e condiviso, letto da uno o più test/esempio, mai modificato dall'esecuzione stessa | NON un file che un test/esempio SCRIVE durante l'esecuzione (quello è output, categoria 4) |
| 4 | **`work/`** (output generato) | Una sottocartella **`work/`** (minuscolo, singolare) **accanto** a chi la genera — MAI annidata (`work/work/` è sempre un bug), MAI condivisa tra sample diversi: <br>• un esempio BASIC scrive nel proprio `work/` relativo (es. `samples/Community/Databases/Foo.bas` → `samples/Community/Databases/work/`) <br>• una suite di test scrive nel proprio `work/` dedicato (es. `samples/database/work/` per `tests/GMBASIC.IlBackend.Tests/RddRealFileDriversTests.cs` — nome storico, resta così perché quel test lo referenzia esplicitamente) | NON in root, NON nella cartella `samples/Fixtures/`, NON in una cartella condivisa fra sample diversi (ognuno il proprio `work/` locale) |

### 11.2 Checklist prima di generare/salvare un file nuovo

1. **È un test con asserzioni (xUnit `[Fact]`/`[Theory]`)?** → categoria 1, `tests/`.
2. **È un programma `.bas` completo, compila E gira correttamente?** → categoria 2,
   `samples/Community\|Commercial\|Native/`. Verificalo PRIMA di committarlo (Conformance
   + `vmtest`, non fidarti del solo "non crasha").
3. **È un dato di input che un test/esempio legge e non modifica mai?** → categoria 3,
   `samples/Fixtures/` (piatta, senza sottocategorie, vedi §9.3).
4. **È un file che un test/esempio SCRIVE come output della propria esecuzione?** →
   categoria 4, dentro un `work/` accanto a chi lo scrive. Prima di aggiungere un path
   relativo di scrittura in un nuovo `.bas`, usa esattamente `"work/nomefile"` — non
   `"Work/"` (maiuscolo incoerente), non un path assoluto, non la cartella del chiamante.
5. **Nessuna delle 4 sopra, è solo per verificare/debuggare qualcosa al volo?** → NON va
   in `samples/` né in root. Usa `/tmp`, o uno scratch esplicitamente autorizzato e
   cancellato a fine sessione (§9.5). Se il tool ti serve in modo persistente, chiedilo
   esplicitamente all'utente invece di infilarlo silenziosamente in una cartella sample.

### 11.3 Segnali che qualcosa è finito nel posto sbagliato

- Un file `.bas` sciolto fuori da `samples/Community\|Commercial\|Native/<Categoria>/`.
- Un file dentro `samples/Fixtures/` che cambia contenuto da un'esecuzione all'altra
  (le fixture sono statiche — se cambia, è output, non fixture).
- Una cartella `work/` con dentro un'altra `work/`, o un `work/` che raccoglie output di
  PIÙ sample diversi.
- Un `.csproj` senza un solo `[Fact]`/assert dentro `samples/` invece che sotto `tests/`.
- Qualunque cosa gitignorata che accumula file per mesi senza che nessuno la ripulisca:
  se è scratch legittimo (categoria 4) resta piccola e coerente con chi la genera; se
  cresce in modo disordinato (come `samples/database/` prima della pulizia del
  2026-08-24), è un segnale che qualcuno non ha seguito questo protocollo.

## 12. Infrastruttura di audit e dispatch — come implementare un nuovo comando rispettandola

> **DIRETTIVA.** Dal refactor 2026-08-30/31, GMBasic ha un'**infrastruttura di audit automatico** e
> un **architettura di dispatch dichiarativo** per i 4 backend (IL, PCodeVM, VM/C,
> C99Native). Ogni nuovo comando/funzione DEVE essere implementato in modo che questa infrastruttura
> lo conti correttamente e ne individui i gap — **mai** aggiungere un builtin "fuori dall'audit".
>
> **Regole operative (riepilogo):** (1) copertura = superficie canonica **982 funzioni StdLib**, la
> stessa per i 4 backend; (2) dopo ogni builtin nuovo: `dotnet run --project tools/audit -- --all` e
> verificare che compaia in `implementate`; (3) TokenKind = chiave canonica, MAI il lexeme
> (violazioni oggi 733; C99Native migrato no); (4) mai stub/inline: implementazione nel
> runtime condiviso `gmb_runtime_c`, verifica `tools/audit/no_stub.py`; (5) niente switch monolitici
> (§0quater), C99Native dispatcha per **tabella lookup**; (6) la qualifica `NS.FUNZIONE` si risolve
> nel parser, il namespace non si dispatcha mai; (7) manifest rigenerati SOLO con `--all`. Stato
> dettagliato e piano: `AiWiki/01-Projects/GMBasic/Todo/(open) - TokenKind-Symbol-Dispatch-Unificato.md`.

### Dettaglio infrastruttura — SPOSTATO

> Superficie canonica (982 funzioni), comandi `gmb_audit`, architettura dispatch dichiarativa,
> regola d'oro del TokenKind ed esempio `FINANCE.REALRATE` sono in **Knowledge/Knowledge-TokenKind-Lexer-Parser-Linker.md §7**
> (lettura OBBLIGATORIA in AGENTS §0). Qui resta la checklist operativa §12.3 (qui sotto).
### 12.3 Checklist: come implementare un nuovo comando/funzione rispettando l'infrastruttura

Prima di aggiungere un nuovo builtin (in aggiunta alla checklist §4):

1. **[ ] È un comando o una funzione?** Comando = niente parentesi, `RegisterCommand` legacy a spazio.
   Funzione = parentesi, ritorna un valore. (§1-§2)
2. **[ ] Il nome ha un TokenKind dedicato?**
   - Se SÌ → dispatch per TokenKind (IL/PCodeVM) o per il TokenKind nella tabella (C99Native).
   - Se NO (builtin di dominio) → dispatch per nome, MA dichiarato nella tabella del backend.
3. **[ ] L'implementazione è nel runtime condiviso, mai inline nei backend?** (§0bis) Il backend
   EMETTE/chiama la funzione `gmb_*` del runtime — mai una copia della logica, mai uno stub
   (return 0/dummy). Verifica che la funzione esista IMPLEMENTATA (non solo dichiarata) nel runtime.
4. **[ ] Il conteggio lo vedrà?** Dopo l'implementazione esegui:
   ```
   dotnet run --project tools/audit -- --all
   ```
   e verifica che il nuovo builtin compaia in `implementate` del backend. Se NON compare, il dispatch
   non è dichiarato nel modo che l'audit legge — correggi.
5. **[ ] Il gap è tracciato?** Se il builtin NON è implementato in un backend, deve restare nella
   `non_coperte_lista` del manifest di quel backend (il gap è visibile, non nascosto).
6. **[ ] Non viola la regola d'oro?** Esegui `--tokenkind-class`: se il nuovo builtin ha un TokenKind
   di dispatch ma il backend lo risolve per lexeme, appare nelle violazioni — accettabile solo se il
   nome NON ha TokenKind (documentato), altrimenti è un bug da correggere.
7. **[ ] Non aggiunge switch monolitici?** (§0quater) Se il builtin richiede logica nel backend, va nel
   file di dominio esistente (`*.Builtins.<Dominio>.cs`, `gmb_syscall_*.c`, `gmb_c99_emit_builtin.*`),
   MAI in un nuovo case nel file principale del dispatcher.
8. **[ ] Ha aggiornato il registro?** Se è una funzione StdLib nuova, `StdLib` la registra
   automaticamente (BuiltinProcedures). Se è un comando, `RegisterCommand`. Il manifest si rigenera
   con `--all` — NON modificare i manifest a mano.
9. **[ ] Non è uno stub?** Esegui `tools/audit/no_stub.py --quiet` (exit 1 per CI): il gate parsa
   ogni handler con bilanciamento parentesi e flagga EMPTY / GUARD_ONLY / STUB_ZERO /
   TABELLA_SENZA_DISPATCH. Un handler con corpo vuoto o che fa solo `GML_VM_REQUIRE();`/`return 0;`
   NON conta come implementato — la voce in tabella/case non basta (§0bis, lezione 6.5.2).
10. **[ ] C99Native: l'emissione è verificata dall'harness?** Per i builtin del C99Native esegui il
    driver (`gmb_driver`, 6.1.12) su un sample che usa il builtin e confronta l'output C col golden
    del dominio. La build da sola NON scopre builtin dichiarati in tabella ma non raggiungibili
    (es. i qualificati `FINANCE.PMT` prima di 6.1.13).

## REGOLA DI SEPARAZIONE DEI DUE COMPILATORI (C# e C) — futura e inderogabile

> Il compilatore **C#** e il compilatore **C** sono e resteranno **fisicamente separati e
> indipendenti**: ciascuno deve funzionare da solo (parse -> link -> codegen -> esecuzione del
> proprio mondo), senza richiamare l'altro e senza condividere implementazioni (niente bridge,
> niente riuso cross-lingua).
> - Se una funzionalità del linguaggio esiste in un compilatore e NON nell'altro, va
>   **implementata nel suo mondo** (mai un wrapper/ponte verso l'altro, mai una implementazione
>   parziale condivisa).
> - **Qualunque ponte, bridge, P/Invoke, riuso improprio o implementazione parziale che mescola
>   i due compilatori va ELIMINATA o CORRETTA SUBITO, appena la si incontra.**
> - **UNICA eccezione ammessa**: gli **LLM embedded** (motore MLX/llama nativo) restano **solo in
>   C** e vengono usati dal C# **solo come libreria via P/Invoke** (nessun altro componente C è
>   raggiungibile dal C#, e nessun componente C può chiamare C#).
> - Ogni nuova funzionalità va progettata e verificata **in modo indipendente sui due lati**
>   (parità di comportamento, non di codice).

## Build & Run

```sh
dotnet build GMBASIC.sln
```

This is a monorepo unifying the deprecated GM-Basic and GMBasicAI repos: no single "run the
interpreter" entry point exists, because there are three independent backends. Each has its own
entry point:

```sh
# IL Backend (pure C#, framework-dependent JIT by default; -n = NativeAOT)
dotnet run --project Executor -- <file.bas>            # IL compilato, JIT (Executor managed, solo IL; richiede .NET 10)
dotnet run --project REPL -- -n <file.bas>             # -n/--native: eseguibile NativeAOT (publish AOT, host REPL)

# VM in C (external process gmb_vm_host, for quick verification)
# richiede il binario Community: cmake -S native/gmb_vm_c -B native/gmb_vm_c/build && cmake --build native/gmb_vm_c/build
# (poi GMBASIC_VM_HOST=native/gmb_vm_c/build/gmb_vm_host, o copialo accanto all'eseguibile del test)
dotnet run --project tests/GMBASIC.Conformance -- vmtest <file.bas>

# C99 transpiler (generates .c, compiles with `cc` against the shared C runtime, runs it)
dotnet run --project tests/GMBASIC.Backend.C99.Tests -p:GmbEdition=Commercial -p:GmbBackendC99=true -- --file=<file.bas>
```

Development mode (bypasses the licensing gate) — set `GMBASIC_DEV_MODE=1` before any of the
commands above.

## Architecture

Front-end (shared by all three backends, all C#):

```
Lexer → Parser → Linker → Compiler (AST/P-Code)
```

From there, compilation forks into **three independent backends** — no C# PCodeVM (unlike the
deprecated GM-Basic repo, this repo never had one):

| Backend | Language | Output |
|---|---|---|
| **IL Backend** | Pure C#, no bridge to C | IL compilato in-process (JIT, framework-dependent) di default / `-m`; eseguibile NativeAOT via `-n` (IL emission) |
| **VM in C** | Pure C | Executes the P-Code via a C virtual machine (Clipper-style: bytecode ships with the executable) |
| **C99 transpiler** | Pure C output (C# does the generating) | Direct C99 source, no VM, no bytecode at runtime |

The VM in C and the C99 transpiler share the same C runtime library (`native/gmb_runtime_c/`) — no
duplicated built-in implementations between the two.

## Concurrency (GPM)

Cooperative multitasking with green threads (goroutine-style `GO SUB`/channels), modeled on Go's
GPM (M:P:G). **Each backend has its own GPM implementation** — VM/C uses a pthread-based model,
C99 a green-thread model; see `docs/GPM-Comparazione-Implementazioni.md` for the detailed
comparison and history of abandoned approaches. Language surface (same across backends):

```basic
' Start a concurrent task
GO SUB BackgroundTask()

' Synchronization
WAIT      ' Wait for all GO tasks
SEND ch, value    ' Channel send
RECEIVE ch => var ' Channel receive

' Sleep without blocking the scheduler
CALL SleepAsync(1000)
```

# MLX MoE — Sorted gather prefill (fix gap prefill/decode)

Stato: 2026-09-03. Regola suprema applicata: copia/adattamento **1:1 dalla reference mlx_lm**
(`mlx_lm/models/switch_layers.py` `SwitchGLU`/`_gather_sort`), nessuna ipotesi custom.

## Problema

Gli ffn MoE del motore chiamavano `mlx_gather_qmm(..., sorted_indices=false)` **sempre**, anche a
prefill (batch grande). La reference mlx_lm, invece, ordina quando `indices.size >= 64`
(= `n_tokens * top_k >= 64`): sorta le righe per esperto e usa il percorso **sorted** di gather_qmm
(gruppi contigui per esperto = efficiente). Il gather unsorted a batch prefill era il collo:

- prefill MoE (GMB_PHASE): ffn = 87-94% del tempo.
- 35B-A3B prefill ~3.7x sotto mlx_lm eager, tutto nell'ffn.

## Fix (layout 1:1 mlx_lm SwitchGLU)

Branch `do_sort` attivo quando `n_tokens * top_k >= 64` (identico a mlx_lm), replicando
`_gather_sort`/`_scatter_unsort` in C:

1. `tt` = flat `top_inds` (T·K) uint32; `order = argsort(tt)`; `inv = argsort(order)`.
2. righe token duplicate per slot: token = `order//K` (via float divide + cast) →
   `take_along_axis(x1, axis=0)` con indices `(M,1,1,1)` → rows `(M,1,1,H)` → reshape `(M,1,H)`.
3. `idx_sorted = tt[order]` (1-D, M), ordinato crescente.
4. `gather_qmm(gate/up/down, x=(M,1,H), rhs=idx_sorted, sorted_indices=true)` → out `(M,1,OD)`
   (shape verificata empiricamente vs python, inclusi i trailing singleton).
5. unsort: `take_along_axis(down_out, axis=0)` con `inv` reshape `(M,1,1)` → `(M,1,H)`
   (NOTA: `mlx_take` C = flatten semantics `axis=None`, NON gather su axis0 → usare
   `take_along_axis`).
6. reshape `(T,K,H)`, scale per probs, `sum` su K → `moe_out (1,T,H)`.

N.B. `mlx_take(&r, a, idx)` sulla C API fa flatten (`a.reshape(-1)[idx]`): bug già colto (duns
diveniva 1-D size M).

Funzioni modificate in `native/gmb_host_ai_mlx/gmb_host_ai_mlx.c` (scoring identico a quella
esistente per architettura):

- `qwen3_5_moe_ffn_block` (Qwen3.6-35B-A3B): probs = `take_along(gates_sm, top_inds)`, norm_topk opz.
- `qwen3_moe_ffn_block` (Coder-30B-A3B, A10B, gpt): idem gates_sm + norm_topk opz.
- `mixtral_ffn_block` (Mixtral-8x22B): probs = `softmax(take_along(gates, top_inds))`.
- Non toccati: `gpt_oss_ffn_block` (già sorted condizionale `!unsort_moe`); `glm4_moe_ffn_block`
  (path host-dependent: readback top_inds, e_score_correction_bias, imatrix — refactor separato, fuori target).

Decode invariato (n_tokens=1 → `top_k < 64` → path unsorted, come la reference).

### Perché VM (1107-1108 BuiltInFunction) ≠ StdLib (1115 funzioni)?

La differenza NON è un gap: le VM eseguono funzioni via **BuiltInFunction** OPPURE via **SysCall**
(dispatch per-namespace nel Compiler). Il conteggio enum (1107/1108) conta i BuiltInFunction unici, mentre
alcuni BuiltInFunction coprono PIÙ funzioni StdLib (es. `EofFunc`/`LEDGER_EOF` → DBF.EOF/ISAM.EOF/LEDGER.EOF),
e molte funzioni DB/ISAM/LEDGER/SPEED/IO sono emesse come **syscall** (non enum). Quindi 1115 funzioni
StdLib = 1108 BuiltInFunction + syscall per-namespace + comandi.

**Verifica 2026-08-29**: tutte le 1115 funzioni StdLib hanno un percorso VM (BuiltInFunction o syscall).
I 4 mancanti trovati (LEDGER.EOF, MATRIX.MULTIPLY, CRYPTOGRAPHY.KEYGEN, CONCURRENCY.SleepAsync) sono stati

## Fatto accertato (pre-requisito)

`mixtral_attention_block` aggiorna la KV con `mlx_concatenate_axis(&k_full, kv, 2)` **a ogni step**:
le shape del passo crescono → il decode-step intero NON e' compilabile (mlx.compile richiede shape
statiche). mlx_lm eager (reference) fa lo stesso concat e infatti non compila il decode. rapid usa
cache a buffer fisso.

Misura odierna (engine vs mlx eager, Mixtral): decode ctx corto engine ~5.3 vs mlx ~7 (1.3x);
ctx 6658: engine (ctx4096 ~2.9-4.0) PIU' veloce di mlx eager (~1 tok/s). Il gap grosso e' verso
rapid (compile+paged), non verso mlx eager.

### Analisi di fattibilità (2026-09-03, dal codice)

- `mixtral_attention_block` (riga ~3787): cache `[1,n_kv,L,hd]`, ogni step `k_full=concat(k_cache,k_rope,axis=2)`.
- `gmb_mlx_gqa_sdpa` (`gmb_mlx_ops.h:113`) con window<=0 delega a `mlx_fast_scaled_dot_product_attention(...,"causal")`
  che deriva la lunghezza chiavi dalla SHAPE di k (offset=kL-qL, fast.cpp). Cache padded a shape statica
  => la modalita' causal guarderebbe i token futuri (zeri). PER SDPA su cache statica servono: shape statica
  padded `[1,n_kv,max_ctx,hd]` + MASCHERA ADDITIVA mode="" con 0 per j<=pos e -inf oltre (la mask e' dato,
  non shape) — stesso meccanismo del branch window (gmb_mlx_ops.h:67-105).
- Scrittura posizionale con le sole op mlx = where(rowsel, k_new, old) => copia O(max_ctx) per step per layer
  (no in-place in mlx). A max_ctx>=4096 e' ~ concat; NON basta per rapid-parity: serve un **kernel Metal
  custom di scatter in un buffer persistente** + SDPA che legge buffer+offset (sottosistema KV dedicato,
  non un patch). Per la sola Fase B (compile) la maschera additiva + where-update bastano come primo step
  funzionante; il kernel in-place e' l'evoluzione successiva.
- Runner: cache per-layer create nel loop del decode (vedere k_cache/v_cache init e `has_cache`); dimensione
  max_ctx = max_len effettiva (non 128k: allocare solo la max vista, con trim rolling kv_max_tokens).

## 1. Definizione tassonomica

| Famiglia | Chi lo genera | Cosa rappresenta | Esempi attuali |
|---|---|---|---|
| **L_*** | **Lexer** (dalla grafia sorgente) | keyword di struttura/statement, operatori/delimitatori, tipi primitivi, parole del comando a spazi, costanti letterali | `If`, `For`, `Print`, `Dbf`, `Use`, `Add`(generico), `StringType`, `As`, `True`, `PolarX`→ma PolarX è P se è risoluzione |
| **P_*** | **Parser/Linker** (sintetizzati dalla risoluzione) | nome qualificato `(ns, funzione)` univoco; **sub-comando** di statement (composto multi-parola); **comando composto**; **membro di oggetto**; **token di disambiguazione** per collisioni (stesso lexeme in ns diversi, o parola statement E funzione); **alias/legacy canonici** (Sqr vs Sqrt); token non presenti nel sorgente come singola parola | `TorchAdd`, `MatrixAddColVector`, `McpServerAdd`, `AiSubPlugins`, `AiPermission`, `Meta` |

Criterio d'assegnazione (checklist per ogni token):

1. Il lexeme di questo token appare nel sorgente **come una sola parola con grafia univoca e non
   ambigua** ed è dispatchato **subito** dal lexer? → **L_***.
2. Il token è il **risultato della risoluzione** di un nome (qualificato `NS.NOME`, o nudo ambiguo),
   di un **sottocomando composto** (più parole: `AI MCP SERVER ADD`), di un **membro** (`.Campo`),
   o di una **collisione** (stesso lexeme con significati diversi)? → **P_***.

### Casi canonici "confusi" oggi (da riclassificare in P_*)

1. **P_* qualificate già esistenti**: `TorchAdd`, `MatrixAddColVector`, `OptimizePowell`, `PolarX` —
   il lexeme non coincide con la grafia (`"ADD"`, `"POLAR_X"`). Già corrette per costruzione.
2. **P_* sub-comando di statement**: oggi il parser le riconosce per-token ma le converte in stringa
   (`mutex_action`/`win_name`/`verb`/`go_args[0].var`) e l'emitter le ricompare per-nome.
   Esempi C99Native residui 2026-09-08: `AI MCP SERVER ADD|REMOVE|ENABLE|DISABLE`,
   `REGISTER TOOL|AGENT`, `UNREGISTER TOOL` (`st_mcp`), verbi `AI PERMISSION`/`AI PLUGINS`
   (`emit_ai_domain`), `SPRITE GETPIXELS`/`SPRITE LOAD`. Tokens MCP/`AiSub*` esistono già
   nell'enum (`McpServerAdd`, `McpRegisterTool`, `AiSubPlugins`, `AiPermission`, `AiSubDiscover`, …)
   → il parser deve **salvare il token**, non la stringa.
3. **P_* collisione tra namespace**: stesso nome funzione in più ns (es. `SHARPERATIO` in METRICS e
   PORTFOLIO; `CVAR`; …). Già risolto nel C99Native con chiave `(ns, token)`; in tassonomia L/P il
   token risolto e univoco è P_*.
4. **P_* parola statement E funzione** (`RUN`, `SELECT`, `GET`, `SET`, `USE`…): il lexeme L_* è
   ambiguo; il significato funzione va risolto dal parser a un P_* di disambiguazione (non forzare
   nel `_builtInFunctionMap` — esclusione deliberata documentata).
5. **P_* membri di oggetto**: `.Count/.Peek/.Body/.Description` — membri su istanza, sintetizzati
   dal parser dopo il punto; alcuni hanno già token nel C99Native (token "member" aggiunti 2026-09-08).
6. **P_* alias/legacy**: `SQRT` alias di `Sqr` risolto a `Sqrt`; alias `IMPORT ... AS` (namespace
   virtuale) risolti al ns fisico nel parser.

> **Regola di principio (utente, 2026-09-08):** nel codice NON esistono stringhe di confronto
> come chiavi di dispatch: ogni parola confrontata è un membro dell'enum TokenKind. I token che
> **compaiono nel BASIC** (keyword/grafie sorgente) restano token "normali" (lexer/parsing).
> I token che **non compaiono nel BASIC** (fabbricati dal parser/lowering/disambiguazione) hanno
> il **prefisso `P_*`**.

# Audit emitter C# — come è stata ricostruita la lista (e le enormi difficoltà)

**Data:** 2026-08-28 · **Backend:** emitter C# (transpiler C#→C, ``)

## Risultato

| Superficie | Totale | Implementate | Non coperte |
|---|---|---|---|
| Funzioni StdLib | **1115** | **1052** (94.4%) | **63** |

## Come è stata recuperata la lista (metodo finale, manuale)

1. **Base canonica**: funzioni StdLib `(ns, nome, TokenKind)` da `common/StdLib/StdLib.*.cs`
   (`new NativeProcedureDefinition` + coppia `Tk?(TokenKind.X, "Nome")`), deduplicate per `(ns, nome)`: **1115**.

2. **Nomi case gestiti dall'emitter**: si estraggono i **case label** reali del C99 emitter
   (`C99CodeEmitter.Builtin.cs` + partial `Stats.cs`, `Collections.cs`, `File.cs`, `Console.cs`, ...):
   - righe che iniziano con `"NAME"` in uno switch-expression;
   - `case "NAME":` (old-style, es. Stats.cs/Collections.cs);
   - `if (name is "X" ...)` pre-switch (es. `INKEY`);
   - or-chain `"A" or "B" ...` (tutti i nomi, non solo il primo).

3. **Copertura per nome**: una funzione è implementata se il suo `nome.upper()` è tra i case label.
   Questo è il metodo **affidabile** (dà 984/1115).

4. **Verifica manuale dei candidati**: i ~131 candidati non coperti vengono verificati **uno per uno**
   con `grep '"NOME"'` nei file emitter C#. 0 occorrenze = vero gap. **73** risultano coperti da
   case multi-riga/or-chain (falsi negativi del passo 2), **63** sono veri gap.
   Risultato finale: **1052/1115 (94.4%)**.

5. **Comportamento dei non gestiti**: il default del main switch è
   `throw new NotSupportedException("C99: builtin non implementato: {name}")` — errore esplicito
   a compile-time, **mai stub**.

## LE ENORMI DIFFICOLTÀ — perché 5 approcci hanno fallito prima del conteggio manuale

L'emitter C# è strutturalmente il backend **più difficile da analizzare staticamente** perché il suo
dispatch non è un singolo meccanismo, ma 5+ forme miste:

1. **Blocchi namespace**: `if (ns == "CONVERT") { return name switch { "A", "B", ... } }` — alcuni ns
   (CONVERT, CLIP, ATOMIC, CONTEXT, POOL, SYNCMAP, SYSTEM, SQL, LEDGER, JSON, CONVERSIONS, AI, COMPRESSION,
   MEMORYMAP, MEMORY, WINDOWS, GRAPHICS, TYPEINFO, PROVIDER) hanno uno switch dedicato.

2. **Main switch con guardie**: `return name switch { "SIN" when bf.Args.Length > 0 => sin(...), "LASTREC"
   when ... && ns is "DBF" or "RDD" => ..., }` (riga ~894–2400). Ogni case ha una guardia `when` che può
   contenere `ns is "DBF" or "RDD"` (virgolette dentro la guardia!) e l'`=>` può stare su righe successive.

3. **Dispatch per TokenKind, non per nome**: il blocco AI usa `switch (bf.Name.Kind)` (es. `TokenKind.AiOcr`),
   NON il nome stringa. Un analisi per nome lo sbaglia.

4. **if-diretti**: `if (ns == "MOUSE") return "0";`, `if (ns == "CONSOLE" && name is "ALERT" or "CONFIRM")
   return "1.0";`, `if (ns == "CHART" && name == "CREATE") return "gmb_gfx_chart_create()"` — non sono
   switch, sono return diretti.

5. **Old-style switch** in partial per dominio: `case "TSMA":` (Stats.cs), `case "QUERY" or "QUERYDIST":`
   (Collections.cs) — sintassi C# pre-switch-expression, con `case` al posto delle stringhe.

6. **Multi-riga**: `"NOW" when bf.Args.Length == 0 && ns is "DATETIME" or "DT"` sulla prima riga,
   `=> gmb_dt_now()` sulla riga successiva. Qualsiasi parser che richiede `=>` sulla stessa riga li perde.

7. **Or-chain**: `"CSTR" or "STR" when ...` — un parser che prende solo il primo nome perde `STR`,
   `"CHIPDF" or "CHISQUAREDPDF"` perde `CHISQUAREDPDF`, ecc.

### I fallimenti successivi (perché le regex erano una trappola)

| Tentativo | Metodo | Risultato | Bug |
|---|---|---|---|
| 1 | regex `if (ns=="X")...return name switch` per blocco | 0 coperte | non matchava il main switch |
| 2 | switch-expression + guardie inline | 277/1115 | `block_ns` non resettato (attribuzione ns sbagliata) |
| 3 | or-chain + old-style + guardie | 935/1115 | multi-riga perso (DATETIME/AI/MATRIX) |
| 4 | parentesi bilanciate | 1016/1115 | guardie con virgolette (`when ns is "DBF"`) tagliavano il case |
| 5 | solo nomi inizio-riga | 984/1115 | perde or-chain (`"CSTR" or "STR"`) e case dopo `when` |
| 6 | "miglioramento" con split su ` when ` | 707/1115 | REGRESSIONE: il `" when "` non è sempre presente (guardie con `&&` e multi-riga) |

**Lezione**: ogni "semplificazione" della regex spostava il bug altrove (guardie con virgolette, `=>`
su riga successiva, or-chain, dispatch per Kind, if-diretti). Il C99 non è parsabile in modo robusto con
espressioni regolari perché il suo linguaggio ha 5 forme sintattiche intrecciate. Il metodo **manuale**
(case label per nome + grep di conferma per ogni candidato) è l'unico che ha prodotto un numero stabile
e verificato: **1052/1115**.

# Audit PCodeVM — come è stata ricostruita la lista di copertura

2. **Dispatch**: `PCodeProcessor.Builtins.cs` → `switch (fn)` su `BuiltInFunction.*` (1040 case) +

   `switch ((SysCall)code)` (377 case). `PCodeProcessor.cs:676` → `switch (opcode)` (143).

   `InvalidOperationException("... non gestito dalla VM")` — errore esplicito, mai stub.

- **Conteggio enum**: l'enum `BuiltInFunction` ha membri su righe multiple e con valori espliciti

  TTESTPAIRED) → conteggi instabili (1105 vs 1107). Il conteggio **per nome** (`\b[A-Z][A-Z0-9_]{2,}\b`

- **Il "970 syscall VM/C" era un miscount**: contava i `case N:` di TUTTO il file (sub-opcode annidati),

- **I 67 non coperte** sono nei domini: AI/MCP/MEMORY/SKILLS (35), RDD (15), WINDOWS (7), GRAPHICS

> prompt/marketplace, plugins marketplace, MCP refresh/marketplaceget, PROCESS).
> Value-verified vs IL per matrix/rolling/ed/yule/ma/hf/mcp/rdd/memory.

## Come è stata recuperata la lista

1. **Chiave canonica**: come la PCodeVM, la VM/C esegue lo **stesso chunk A1/GMBC** prodotto dal
   Compiler C#: le funzioni sono i valori dell'enum `BuiltInFunction` (1107), i comandi i `SysCall` (377),
   le istruzioni i `OpCode` (143).

2. **Dispatch**: `gmb_vm_exec_builtin` (`native/gmb_vm_c/gmb_vm_core.c`, riga ~3719) →
   `switch (func_code)` con case **numerici** (i valori dell'enum). Il default lancia
   `vm_error("builtin N non implementato")` — mai stub.

3. **Verifica**: si estrae l'enum C# con valori numerici (parse riga-per-riga, gestendo `TTEST = 772, ...`)
   e si confronta con i `case <valore>:` del dispatcher. `case` nel range enum = implementata.

## Difficoltà incontrate (le più grandi dopo il C99)

- **I case sono numerici, non per nome**: il mapping valore→nome richiede un parse corretto dell'enum C#
  (righe multi-membro con valori espliciti). Con un parse errato si ottenevano conteggi instabili.
- **7 case extra non-enum** (43=PI, 128=LU, 129=QR, 141=FV, 143=PV, 155=DB, 591=TI): il VM/C li gestisce
  ma il Compiler C# non li emette mai (non contano nel confronto).
- **La scoperta chiave**: molte delle 134 non-implementate (MATRIX rows/cols, ROLLING*, HTTP, RDD)
  ESISTONO nel runtime condiviso (`gmb_matrix.c`, `gmb_timeseries.c`, `gmb_network.c`) ma il dispatcher
  `gmb_vm_exec_builtin` NON le collega ai case → `vm_error("builtin N non implementato")` a runtime.
  È un bug di **wiring del dispatcher**, non assenza di implementazione runtime.
- **Il "970 syscall" era un miscount**: contava tutti i `case N:` del file (978), ma 617 sono sub-opcode
  annidati. Il numero reale dei syscall è **375/377** (mancano `124 DBF_APPEND_RECORD`, `296 WINDOW_THEME`).

/* Convert integer to decimal digit literals.  */
#define DEC(n)                   \
  ('0' + (((n) / 10000000)%10)), \
  ('0' + (((n) / 1000000)%10)),  \
  ('0' + (((n) / 100000)%10)),   \
  ('0' + (((n) / 10000)%10)),    \
  ('0' + (((n) / 1000)%10)),     \
  ('0' + (((n) / 100)%10)),      \
  ('0' + (((n) / 10)%10)),       \
  ('0' +  ((n) % 10))

/* Convert integer to hex digit literals.  */
#define HEX(n)             \
  ('0' + ((n)>>28 & 0xF)), \
  ('0' + ((n)>>24 & 0xF)), \
  ('0' + ((n)>>20 & 0xF)), \
  ('0' + ((n)>>16 & 0xF)), \
  ('0' + ((n)>>12 & 0xF)), \
  ('0' + ((n)>>8  & 0xF)), \
  ('0' + ((n)>>4  & 0xF)), \
  ('0' + ((n)     & 0xF))

static int run_process(const char* cmd)
{
    int rc = system(cmd);
    return WIFEXITED(rc) ? WEXITSTATUS(rc) : 1;
}

static void resolve_repo_root(char* out, size_t cap)
{
    char cwd[2048];
    getcwd(cwd, sizeof(cwd));
    snprintf(out, cap, "%s", cwd);
    for (;;) {
        char probe[4096];
        snprintf(probe, sizeof(probe), "%s/GMBASIC.sln", out);
        if (access(probe, F_OK) == 0) return;
        char* slash = strrchr(out, '/');
        if (!slash) { snprintf(out, cap, "%s", cwd); return; }
        *slash = 0;
        if (!*out) { snprintf(out, cap, "/"); return; }
    }
}

/* Risolve le direttive `IMPORT <Ns>` del modulo principale: per ogni namespace con un file
 * `<Ns>.inc` nella cartella include/ della root (marker include/HttpController.inc, speculare
 * a DiscoverSourceFiles/FindRepoIncludeRoot del C#), prepende ricorsivamente il contenuto del
 * modulo (i suoi IMPORT inclusi) al sorgente main — così le classi/UDT dei moduli sono definite
 * prima dell'uso (il parser C99Native è monofile: NAMESPACE è no-op, IMPORT era ignorato).
 * Namespace builtin senza file (AI/MATH/...) → nessun caricamento. Ritorna buffer malloc o NULL
 * se il main non aveva IMPORT risolvibili (in tal caso il chiamante usa il sorgente originale). */
static char* gmb_resolve_imports(const char* main_src, const char* bas_file)
{
    char root[2048];
    resolve_repo_root(root, sizeof(root));
    const char* include_dir = NULL;
    {
        static char incdir[4096];
        char dir[4096];
        snprintf(dir, sizeof(dir), "%s", root);
        for (;;) {
            snprintf(incdir, sizeof(incdir), "%s/include", dir);
            char marker[4096];
            snprintf(marker, sizeof(marker), "%s/HttpController.inc", incdir);
            if (access(marker, F_OK) == 0) { include_dir = incdir; break; }
            char* slash = strrchr(dir, '/');
            if (!slash || !*dir) break;
            *slash = 0;
        }
    }
    if (!include_dir) return NULL;

    /* Colleziona i namespace IMPORT dal sorgente (righe `IMPORT <Ns>` in testa/ovunque). */
    char nss[32][64];
    int nns = 0;
    {
        const char* s = main_src;
        while (*s) {
            const char* nl = strchr(s, '\n');
            size_t linelen = nl ? (size_t)(nl - s) : strlen(s);
            const char* line = s;
            /* salta spazi iniziali */
            while (linelen > 0 && (*line == ' ' || *line == '\t')) { line++; linelen--; }
            if (linelen >= 6 && strncasecmp(line, "IMPORT", 6) == 0
                && (linelen == 6 || line[6] == ' ' || line[6] == '\t')) {
                const char* p = line + 6;
                while (*p == ' ' || *p == '\t') p++;
                char ns[64]; int i = 0;
                while (*p && *p != ' ' && *p != '\t' && *p != '\r' && *p != '\n' && i < 63) ns[i++] = *p++;
                ns[i] = 0;
                /* salta WITH ALIAS / (selettivo) / .* — prendiamo solo il namespace semplice */
                if (i > 0 && nns < 32) {
                    int dup = 0;
                    for (int k = 0; k < nns; k++) if (strcasecmp(nss[k], ns) == 0) dup = 1;
                    if (!dup) { snprintf(nss[nns], sizeof(nss[nns]), "%s", ns); nns++; }
                }
            }
            if (!nl) break;
            s = nl + 1;
        }
    }
    if (nns == 0) return NULL;

    /* Accumula i sorgenti dei moduli (prima i loro IMPORT, ricorsione a 1 livello dei .inc). */
    char* merged = NULL;
    size_t mcap = 0, mlen = 0;
    for (int idx = 0; idx < nns; idx++) {
        /* Cerca il modulo il cui NAMESPACE dichiarato matcha <Ns> (case-insens), NON il nome
         * file: il file può chiamarsi Agent.inc mentre il namespace è AGENTS (convenzione
         * C#: IMPORT AGENTS → include/Agent.inc con `NAMESPACE AGENTS`). Volume case-sensitive. */
        char incfile[4608];
        incfile[0] = 0;
        {
            DIR* d = opendir(include_dir);
            if (d) {
                struct dirent* e;
                while ((e = readdir(d)) != NULL && !incfile[0]) {
                    const char* nm = e->d_name;
                    size_t nl = strlen(nm);
                    if (nl <= 4 || strcasecmp(nm + nl - 4, ".inc") != 0) continue;
                    char full[4608];
                    snprintf(full, sizeof(full), "%s/%s", include_dir, nm);
                    FILE* tf = fopen(full, "rb");
                    if (!tf) continue;
                    fseek(tf, 0, SEEK_END); long tlen = ftell(tf); fseek(tf, 0, SEEK_SET);
                    char* tsrc = (char*)malloc((size_t)tlen + 1);
                    if (tlen > 0 && fread(tsrc, 1, (size_t)tlen, tf) != (size_t)tlen) { free(tsrc); fclose(tf); continue; }
                    tsrc[tlen] = 0; fclose(tf);
                    /* cerca "NAMESPACE <Ns>" (case-insens) nel contenuto */
                    const char* need = NULL;
                    for (const char* q = tsrc; (q = strcasestr(q, "NAMESPACE ")) != NULL; q += 10) {
                        const char* p = q + 10;
                        while (*p == ' ' || *p == '\t') p++;
                        if (strncasecmp(p, nss[idx], strlen(nss[idx])) == 0) { need = nss[idx]; break; }
                    }
                    free(tsrc);
                    if (need) snprintf(incfile, sizeof(incfile), "%s", full);
                }
                closedir(d);
            }
        }
        if (!incfile[0]) continue;   /* builtin namespace senza modulo */
        FILE* f = fopen(incfile, "rb");
        if (!f) continue;
        fseek(f, 0, SEEK_END); long ilen = ftell(f); fseek(f, 0, SEEK_SET);
        char* isrc = (char*)malloc((size_t)ilen + 1);
        if (ilen > 0 && fread(isrc, 1, (size_t)ilen, f) != (size_t)ilen) { free(isrc); fclose(f); continue; }
        isrc[ilen] = 0; fclose(f);
        if (mlen + (size_t)ilen + 2 > mcap) {
            mcap = (mlen + (size_t)ilen + 2) * 2;
            merged = (char*)realloc(merged, mcap);
        }
        memcpy(merged + mlen, isrc, (size_t)ilen);
        mlen += (size_t)ilen;
        merged[mlen++] = '\n';
        free(isrc);
    }
    if (!merged) return NULL;
    if (mlen + strlen(main_src) + 2 > mcap) {
        mcap = mlen + strlen(main_src) + 2;
        merged = (char*)realloc(merged, mcap);
    }
    memcpy(merged + mlen, main_src, strlen(main_src) + 1);
    (void)bas_file;
    return merged;
}

static const char* resolve_vm_host(void)
{
    static char path[2048];
    const char* env = getenv("GMBASIC_VM_HOST");
    if (env && access(env, X_OK) == 0) return env;
    snprintf(path, sizeof(path), "%s/native/gmb_vm_c/build/gmb_vm_host", getenv("GMBASIC_REPO_ROOT") ? getenv("GMBASIC_REPO_ROOT") : ".");
    if (access(path, X_OK) == 0) return path;
    char root[2048];
    resolve_repo_root(root, sizeof(root));
    snprintf(path, sizeof(path), "%s/native/gmb_vm_c/build/gmb_vm_host", root);
    return access(path, X_OK) == 0 ? path : NULL;
}


/* Aggregazione progetto (IMPORT multi-file, mondo C): IMPORT <Ns> può risiedere in
 * include/<Ns>.inc (repo) OPPURE in file compagna della stessa cartella del progetto
 * (es. MyLibrary.inc con NAMESPACE Geometria). Il compilatore managed scansiona la
 * directory: qui prependiamo (in ordine) i contenuti di include/<Ns> risolti e di
 * tutti i file *.inc / *.bas fratelli (escluso il main) prima del sorgente main. */
static int gmb_import_needs_local_files(const char* main_src)
{
    static const char* builtin_ns[] = {
        /* Namespace builtin canonici (specchio gmb_ns_names / IMPORT di un namespace del
         * linguaggio, MAI una libreria di progetto): IMPORT di questi NON deve aggregare i
         * file fratelli della cartella (gmb_aggregate_project) — un IMPORT di un builtin
         * mancante da questa lista (es. OPTIMIZE prima del fix) faceva prependere TUTTI i
         * .bas/.inc compagna, eseguendo codice estraneo (artefatti tipo "eventi registrati"). */
        "JSON","FINANCE","ARRAYS","COLLECTIONS","GRAPHICS","MATH","MATRIX","VECTOR",
        "NET","AI","DBF","ISAM","SQL","RDD","LEDGER","HTTP","CHART","TEAM","IO",
        "SYSTEM","TEXT","CONVERT","AUDIO","TORCH","CHANNELS","TOOLS",
        "ANALYSIS","ATOMIC","AUTH","BLOCKCHAIN","CLIP","COMPRESSION","CONCURRENCY",
        "CONSOLE","CONSTANTS","CONTEXT","CONVERSIONS","CRYPTOGRAPHY","DATETIME","JOY",
        "KDTREE","MEMORY","MEMORYMAP","MOUSE","MUTEX","ONKEY","OPTIMIZE","POOL",
        "PROVIDER","SIGNAL","SPATIAL","SPECIAL","SPEED","STATS","STRINGS","SYNCMAP",
        "TIMESERIES","TRADING","TRADING.BACKTESTS","TRADING.BONDS","TRADING.METRICS",
        "TRADING.OPTIONS","TRADING.PORTFOLIO","TYPEINFO","VECTORDB","WINDOWS",
        "GRAPH","VAULT","NOTE","INGEST","AGENT","BROWSER","COMPUTER","TOOL","UI", NULL
    };
    const char* s = main_src;
    while (*s)
    {
        const char* nl = strchr(s, '\n');
        size_t linelen = nl ? (size_t)(nl - s) : strlen(s);
        const char* line = s;
        while (linelen > 0 && (*line == ' ' || *line == '\t')) { line++; linelen--; }
        if (linelen >= 6 && strncasecmp(line, "IMPORT", 6) == 0
            && (linelen == 6 || line[6] == ' ' || line[6] == '\t'))
        {
            const char* p = line + 6;
            while (*p == ' ' || *p == '\t') p++;
            char ns[64]; int i = 0;
            while (*p && *p != ' ' && *p != '\t' && *p != '\r' && *p != '\n' && i < 63) ns[i++] = *p++;
            ns[i] = 0;
            int builtin = 0;
            for (int k = 0; builtin_ns[k]; k++)
                if (strcasecmp(ns, builtin_ns[k]) == 0) { builtin = 1; break; }
            if (!builtin && i > 0) return 1;   /* namespace locale/esterno → serve i file compagna */
        }
        if (!nl) break;
        s = nl + 1;
    }
    return 0;
}

static char* gmb_aggregate_project(const char* main_src, const char* bas_file)
{
    if (!gmb_import_needs_local_files(main_src)) return NULL;
    char* out = NULL; size_t cap = 0, len = 0;
    char* resolved = gmb_resolve_imports(main_src, bas_file);
    if (resolved) { out = strdup(resolved); len = strlen(out); cap = len + 1; }
    char dir[4096];
    snprintf(dir, sizeof(dir), "%s", bas_file);
    char* slash = strrchr(dir, '/');
    if (!slash) snprintf(dir, sizeof(dir), "."); else *slash = 0;
    const char* mainbase = strrchr(bas_file, '/');
    mainbase = mainbase ? mainbase + 1 : bas_file;
    DIR* d = opendir(dir);
    if (d)
    {
        /* raccogli i nomi e ordinali per robustezza di ordinamento */
        struct dirent* e;
        char names[64][512]; int n = 0;
        while ((e = readdir(d)) != NULL && n < 64)
        {
            const char* nm = e->d_name;
            size_t el = strlen(nm);
            const char* ext = el > 4 ? nm + el - 4 : "";
            if (strcmp(nm, mainbase) == 0) continue;
            if ((!strcasecmp(ext, ".inc")) || (!strcasecmp(ext, ".bas")))
            {
                snprintf(names[n], sizeof(names[n]), "%s", nm);
                /* insertion sort per nome (case-insensitive) */
                int j = n;
                while (j > 0 && strcasecmp(names[j - 1], names[j]) > 0)
                {
                    char tmp[512]; snprintf(tmp, sizeof(tmp), "%s", names[j - 1]);
                    snprintf(names[j - 1], sizeof(names[j - 1]), "%s", names[j]);
                    snprintf(names[j], sizeof(names[j]), "%s", tmp);
                    j--;
                }
                n++;
            }
        }
        closedir(d);
        for (int i = 0; i < n; i++)
        {
            char path[4700];
            snprintf(path, sizeof(path), "%s/%s", dir, names[i]);
            FILE* f = fopen(path, "rb");
            if (!f) continue;
            fseek(f, 0, SEEK_END); long sz = ftell(f); fseek(f, 0, SEEK_SET);
            if (sz > 0)
            {
                char* buf = (char*)malloc((size_t)sz + 1);
                if (buf && fread(buf, 1, (size_t)sz, f) == (size_t)sz)
                {
                    buf[sz] = 0;
                    size_t nl = strlen(buf);
                    if (len + nl + 2 > cap) { cap = (len + nl + 2) * 2; out = (char*)realloc(out, cap); }
                    if (!out) out = (char*)malloc(cap);
                    memcpy(out + len, buf, nl); len += nl;
                    out[len++] = '\n'; out[len] = 0;
                }
                free(buf);
            }
            fclose(f);
        }
    }
    if (!out) return NULL;
    /* appendi il main */
    size_t ml = strlen(main_src);
    if (len + ml + 1 > cap) { cap = (len + ml + 1) * 2; out = (char*)realloc(out, cap); }
    memcpy(out + len, main_src, ml); len += ml; out[len] = 0;
    if (resolved) free(resolved);
    return out;
}

/* Compila .bas -> chunk A1/GMBC con il pipeline 100% C (specchio della REPL nativa
 * AST: lexer -> macro expand -> parser -> linker -> compilatore P-Code). */
static int gmb_compile_c_chunk(const char* bas_file, const char* out_path)
{
    FILE* f = fopen(bas_file, "rb");
    if (!f) { fprintf(stderr, "?file non trovato: %s\n", bas_file); return 2; }
    fseek(f, 0, SEEK_END); long alen = ftell(f); fseek(f, 0, SEEK_SET);
    char* src = (char*)malloc((size_t)alen + 1);
    if (alen > 0 && fread(src, 1, (size_t)alen, f) != (size_t)alen) { fclose(f); free(src); return 2; }
    src[alen] = 0; fclose(f);

    char* merged2 = gmb_aggregate_project(src, bas_file);
    const char* msrc = merged2 ? merged2 : src;
    long mlen2 = (long)strlen(msrc);
    gmb_lex_result_t lx = gmb_lexer_scan(msrc, mlen2);
    gmb_lex_result_t lx2 = gmb_macro_expand(&lx);
    lx.owned_src = NULL;
    char* perr = NULL;
    gmb_program_t prog = gmb_parse(&lx2, &perr);
    if (perr) { fprintf(stderr, "?compilazione C: parse error: %s\n", perr); free(perr); gmb_lex_result_free(&lx2); gmb_lex_result_free(&lx); free(merged2); free(src); return 3; }

    uint8_t* data = NULL; size_t len = 0; char* cerr = NULL;
    int rc = gmb_compile(&prog, &data, &len, &cerr);
    if (rc != 0) { fprintf(stderr, "?compilazione C: %s\n", cerr ? cerr : "errore"); free(cerr); gmb_program_free(&prog); gmb_lex_result_free(&lx2); gmb_lex_result_free(&lx); free(merged2); free(src); return 4; }

    FILE* of = fopen(out_path, "wb");
    if (!of) { fprintf(stderr, "?impossibile scrivere: %s\n", out_path); free(data); gmb_program_free(&prog); gmb_lex_result_free(&lx2); gmb_lex_result_free(&lx); free(merged2); free(src); return 5; }
    fwrite(data, 1, len, of);
    fclose(of);
    free(data);
    gmb_program_free(&prog);
    gmb_lex_result_free(&lx2);
    gmb_lex_result_free(&lx);
    free(merged2);
    free(src);
    return 0;
}

/* Genera il sorgente C99 da un .bas con il pipeline 100% C + emitter nativo. */
static int gmb_emit_c99_source(const char* bas_file, const char* out_path)
{
    FILE* f = fopen(bas_file, "rb");
    if (!f) { fprintf(stderr, "?file non trovato: %s\n", bas_file); return 2; }
    fseek(f, 0, SEEK_END); long alen = ftell(f); fseek(f, 0, SEEK_SET);
    char* src = (char*)malloc((size_t)alen + 1);
    if (alen > 0 && fread(src, 1, (size_t)alen, f) != (size_t)alen) { fclose(f); free(src); return 2; }
    src[alen] = 0; fclose(f);

    /* IMPORT <Ns>: prepende il contenuto di include/<Ns>.inc (moduli riusabili), così le
     * classi/UDT dichiarate nei .inc sono definite prima dell'uso. IMPORT era ignorato. */
    char* resolved = gmb_resolve_imports(src, bas_file);
    char* merged = resolved ? resolved : src;
    long mlen = (long)strlen(merged);

    gmb_lex_result_t lx = gmb_lexer_scan(merged, mlen);
    gmb_lex_result_t lx2 = gmb_macro_expand(&lx);
    lx.owned_src = NULL;
    char* perr = NULL;
    gmb_program_t prog = gmb_parse(&lx2, &perr);
    if (perr) { fprintf(stderr, "?c99: parse error: %s\n", perr); free(perr); gmb_lex_result_free(&lx2); gmb_lex_result_free(&lx); free(resolved); free(src); return 3; }

    char* csrc = NULL; char* eerr = NULL;
    int rc = gmb_c99_emit(&prog, &csrc, &eerr);
    if (rc != 0) { fprintf(stderr, "?c99: emissione: %s\n", eerr ? eerr : "errore"); free(eerr); gmb_program_free(&prog); gmb_lex_result_free(&lx2); gmb_lex_result_free(&lx); free(resolved); free(src); return 4; }

    FILE* of = fopen(out_path, "wb");
    if (!of) { fprintf(stderr, "?impossibile scrivere: %s\n", out_path); free(csrc); gmb_program_free(&prog); gmb_lex_result_free(&lx2); gmb_lex_result_free(&lx); free(resolved); free(src); return 5; }
    fwrite(csrc, 1, strlen(csrc), of);
    fclose(of);
    free(csrc);
    gmb_program_free(&prog);
    gmb_lex_result_free(&lx2);
    gmb_lex_result_free(&lx);
    free(resolved);
    free(src);
    return 0;
}

int gmb_native_compile(const char* bas_file, const char* out_path, gmb_exec_backend_t backend)
{
    if (backend == GMB_EXEC_VMC)
        return gmb_compile_c_chunk(bas_file, out_path);
    return gmb_emit_c99_source(bas_file, out_path);
}

int gmb_native_exec(const char* bas_file, gmb_exec_backend_t backend)
{
    if (backend == GMB_EXEC_VMC) {
        char chunk[2048];
        snprintf(chunk, sizeof(chunk), "/tmp/gmb_exec_%ld.chunk", (long)getpid());
        if (gmb_native_compile(bas_file, chunk, GMB_EXEC_VMC) != 0) return 2;
        const char* host = resolve_vm_host();
        if (!host) { fprintf(stderr, "?gmb_vm_host non trovato (GMBASIC_VM_HOST o build native/gmb_vm_c)\n"); return -1; }
        char cmd[4096];
        snprintf(cmd, sizeof(cmd), "\"%s\" \"%s\"", host, chunk);
        int rc = run_process(cmd);
        unlink(chunk);
        return rc;
    }
    /* c99 */
    char cfile[2048], bindir[2048];
    snprintf(cfile, sizeof(cfile), "/tmp/gmb_exec_%ld.c", (long)getpid());
    snprintf(bindir, sizeof(bindir), "/tmp/gmb_exec_%ld", (long)getpid());
    mkdir(bindir, 0755);
    if (gmb_native_compile(bas_file, cfile, GMB_EXEC_C99) != 0) return 2;
    char root[2048];
    resolve_repo_root(root, sizeof(root));
    /* Link completo (specchio di ReplEngine.cs:660-685): SDL2, brotli, openssl@3.
     * I pkgCcFlags dei pacchetti c-ffi/binaries[c99] non sono ancora risolti in C. */
    char cmd[8192];
    snprintf(cmd, sizeof(cmd),
        "cc \"%s\" %s/native/gmb_runtime_c/src/*.c -I\"%s/native/gmb_runtime_c/include\""
        " -I\"%s/native/gmb_agent_runtime\""
        " -I\"%s/native/gmb_torch/include\" -I/opt/homebrew/include -I/opt/homebrew/opt/openssl@3/include"
        " -lm -lz -lbz2 -lsqlite3 -lcurl -lpcre2-8 -L/opt/homebrew/lib -lSDL2"
        " -L/opt/homebrew/opt/brotli/lib -lbrotlienc -lbrotlidec -lbrotlicommon"
        " -L/opt/homebrew/opt/openssl@3/lib -lcrypto -lssl"
        " -o \"%s/prog\"",
        cfile, root, root, root, root, bindir);
    if (getenv("GMBASIC_DEBUG")) fprintf(stderr, "[cc] %s\n", cmd);
    int rc = run_process(cmd);
    int keep_c = getenv("GMBASIC_KEEP_C") != NULL;
    if (keep_c) fprintf(stderr, "[keep] %s\n", cfile);
    if (rc != 0) { if (!keep_c) unlink(cfile); return 3; }
    snprintf(cmd, sizeof(cmd), "\"%s/prog\"", bindir);
    rc = run_process(cmd);
    if (!keep_c) unlink(cfile);
    snprintf(cmd, sizeof(cmd), "rm -rf \"%s\"", bindir);
    run_process(cmd);
    return rc;
}

const char *gmb_resolve_level_name(gmb_resolve_level_t level) {
    switch (level) {
        case GMB_RESOLVE_API: return "API";
        case GMB_RESOLVE_AX: return "AX";
        case GMB_RESOLVE_DOM: return "DOM";
        case GMB_RESOLVE_CUA: return "CUA";
        default: return "UNKNOWN";
    }
}

int gmb_action_resolver_click(const char *target, gmb_resolved_action_t *out) {
    if (!target || !out) return -1;
    memset(out, 0, sizeof(*out));
    strncpy(out->target, target, sizeof(out->target)-1);
    // Euristica: se target sembra un selettore CSS (#id, .class) → DOM
    if (target[0] == '#' || target[0] == '.') {
        out->level = GMB_RESOLVE_DOM;
        out->provider = "BrowserProvider";
        out->action = "click";
        return 0;
    }
    // Se AX disponibile (macOS) → AX
#if defined(__APPLE__)
    out->level = GMB_RESOLVE_AX;
    out->provider = "MacProvider";
    out->action = "click";
    return 0;
#endif
    // Fallback CUA
    out->level = GMB_RESOLVE_CUA;
    out->provider = "ComputerProvider";
    out->action = "click";
    out->x = 100; out->y = 100; // TODO: Vision → coordinate reali
    return 0;
}

int gmb_action_resolver_type(const char *target, const char *text, gmb_resolved_action_t *out) {
    if (!target || !text || !out) return -1;
    memset(out, 0, sizeof(*out));
    strncpy(out->target, target, sizeof(out->target)-1);
    out->level = GMB_RESOLVE_AX;
    out->provider = "MacProvider";
    out->action = "type";
    return 0;
}

/* capability.c — implementazione Policy */
#include "capability.h"
#include <string.h>
#include <strings.h>
#include <stdio.h>

#define MAX_AGENTS 32
#define MAX_TOOLS 32

typedef struct { char tool[64]; char policy[16]; } tool_policy_t;
typedef struct { char agent[64]; tool_policy_t tools[MAX_TOOLS]; int count; } agent_policy_t;

static agent_policy_t g_policies[MAX_AGENTS];
static int g_policy_count = 0;

static agent_policy_t *find_or_create(const char *agent) {
    for (int i = 0; i < g_policy_count; i++) if (strcasecmp(g_policies[i].agent, agent) == 0) return &g_policies[i];
    if (g_policy_count >= MAX_AGENTS) return NULL;
    strncpy(g_policies[g_policy_count].agent, agent, 63);
    g_policies[g_policy_count].count = 0;
    return &g_policies[g_policy_count++];
}

int gmb_capability_set(const char *agent, const char *tool, const char *policy) {
    if (!agent || !tool || !policy) return -1;
    if (strcasecmp(policy, "allow") != 0 && strcasecmp(policy, "deny") != 0 && strcasecmp(policy, "approve") != 0) return -1;
    agent_policy_t *ap = find_or_create(agent);
    if (!ap) return -1;
    for (int i = 0; i < ap->count; i++) if (strcasecmp(ap->tools[i].tool, tool) == 0) {
        strncpy(ap->tools[i].policy, policy, 15);
        return 0;
    }
    if (ap->count >= MAX_TOOLS) return -1;
    strncpy(ap->tools[ap->count].tool, tool, 63);
    strncpy(ap->tools[ap->count].policy, policy, 15);
    ap->count++;
    return 0;
}

gmb_cap_verdict_t gmb_capability_check(const char *agent, const char *tool) {
    if (!agent || !tool) return GMB_CAP_ALLOW;
    for (int i = 0; i < g_policy_count; i++) if (strcasecmp(g_policies[i].agent, agent) == 0) {
        for (int j = 0; j < g_policies[i].count; j++) if (strcasecmp(g_policies[i].tools[j].tool, tool) == 0) {
            if (strcasecmp(g_policies[i].tools[j].policy, "deny") == 0) return GMB_CAP_DENY;
            if (strcasecmp(g_policies[i].tools[j].policy, "approve") == 0) return GMB_CAP_APPROVE;
            return GMB_CAP_ALLOW;
        }
    }
    return GMB_CAP_ALLOW; // default YOLO (parità AgentPermissionService)
}

int gmb_capability_clear(const char *agent) {
    for (int i = 0; i < g_policy_count; i++) if (strcasecmp(g_policies[i].agent, agent) == 0) {
        for (int j = i; j < g_policy_count-1; j++) g_policies[j] = g_policies[j+1];
        g_policy_count--;
        return 0;
    }
    return -1;
}

#include "credential_vault.h"

#define MAX_CREDS 32
typedef struct { char service[64]; char user[64]; char secret[256]; int used; } cred_t;

int gmb_credential_vault_store(const char *service, const char *user, const char *secret) {
    if (!service || !user || !secret) return -1;
    for (int i = 0; i < MAX_CREDS; i++) if (g_creds[i].used && strcasecmp(g_creds[i].service, service) == 0 && strcasecmp(g_creds[i].user, user) == 0) {

    }
    for (int i = 0; i < MAX_CREDS; i++) if (!g_creds[i].used) {
        strncpy(g_creds[i].service, service, 63); strncpy(g_creds[i].user, user, 63); strncpy(g_creds[i].secret, secret, 255); g_creds[i].used = 1; return 0;
    }
    return -1;
}

    if (!service || !user) return NULL;
    for (int i = 0; i < MAX_CREDS; i++) if (g_creds[i].used && strcasecmp(g_creds[i].service, service) == 0 && strcasecmp(g_creds[i].user, user) == 0) return g_creds[i].secret;

}

    for (int i = 0; i < MAX_CREDS; i++) if (g_creds[i].used && strcasecmp(g_creds[i].service, service) == 0 && strcasecmp(g_creds[i].user, user) == 0) { g_creds[i].used = 0; return 0; }

}

}
/* gmb_agent_action.c — implementazione AgentAction runner (Fase 5 fondamenta).
 * Riusa i componenti già testati del runtime (gmb_agent_runtime): ToolRegistry,
 * ActionResolver (UI), CDP browser. Nessuna logica duplicata (§0bis). */
#include "gmb_agent_action.h"
#include "gmb_browser_cdp.h"
#include "tool_registry.h"
#include "action_resolver.h"
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

int gmb_agent_action_run(const char* brain_text, char* out_obs, size_t cap) {
    if (!out_obs || cap == 0) return -1;
    out_obs[0] = 0;
    if (!brain_text || !*brain_text) return 1;

    /* 1) isola l'oggetto azione: {"action":{...}} oppure {"tool_call":{...}} */
    const char* body = brain_text;
    int has_action = gmb_cdp_json_has(body, "action");
    int has_call = gmb_cdp_json_has(body, "tool_call");
    if (!has_action && !has_call) return 1;

    /* 2) estrae tool/name e args/arguments */
    char tool[128] = "";
    char args[2048] = "";
    if (has_action) {
        if (gmb_cdp_json_get_str(body, "tool", tool, sizeof(tool)) != 0)
            gmb_cdp_json_get_str(body, "name", tool, sizeof(tool));
        gmb_cdp_json_get_str(body, "args", args, sizeof(args));
    } else {
        if (gmb_cdp_json_get_str(body, "name", tool, sizeof(tool)) != 0)
            gmb_cdp_json_get_str(body, "tool", tool, sizeof(tool));
        gmb_cdp_json_get_str(body, "arguments", args, sizeof(args));
    }
    if (!tool[0]) { snprintf(out_obs, cap, "{\"obs\":\"action senza tool\"}"); return -1; }

    /* 3) dispatch sul runtime */
    if (strcmp(tool, "tool.search") == 0 || strcmp(tool, "TOOL.SEARCH") == 0) {
        char q[256] = "";
        gmb_cdp_json_get_str(args, "query", q, sizeof(q));
        char* j = gmb_tool_registry_search_json(q);
        snprintf(out_obs, cap, "{\"obs\":%s}", j ? j : "[]");
        if (j) free(j);
        return 0;
    }
    if (strcmp(tool, "ui.find") == 0 || strcmp(tool, "UI.FIND") == 0) {
        char target[256] = "";
        gmb_cdp_json_get_str(args, "target", target, sizeof(target));
        char* j = gmb_action_resolver_find(target);
        snprintf(out_obs, cap, "{\"obs\":%s}", j ? j : "{\"found\":false}");
        if (j) free(j);
        return 0;
    }
    if (strncmp(tool, "browser.", 8) == 0 || strncmp(tool, "browser_", 8) == 0) {
        gmb_cdp_t* cdp = gmb_cdp_singleton();
        if (!cdp) { snprintf(out_obs, cap, "{\"obs\":\"browser non connesso\"}"); return -1; }
        const char* verb = tool + 8;
        char* out = NULL;
        char body[2048];
        int rc = -1;
        if (strncmp(verb, "navigate", 8) == 0) {
            char url[512] = "";
            gmb_cdp_json_get_str(args, "url", url, sizeof(url));
            char esc[1024] = "";
            gmb_cdp_json_escape(url, esc, sizeof(esc));
            snprintf(body, sizeof(body), "{\"url\":\"%s\"}", esc);
            rc = gmb_cdp_command(cdp, "Page.navigate", body, &out);
            snprintf(out_obs, cap, rc == 0 ? "{\"obs\":\"navigated\"}" : "{\"obs\":\"%s\"}", rc == 0 ? "ok" : (gmb_cdp_last_error(cdp) ? gmb_cdp_last_error(cdp) : "err"));
        } else if (strncmp(verb, "evaluate", 8) == 0) {
            char expr[1024] = "";
            gmb_cdp_json_get_str(args, "expression", expr, sizeof(expr));
            char esc[2048] = "";
            gmb_cdp_json_escape(expr, esc, sizeof(esc));
            snprintf(body, sizeof(body), "{\"expression\":\"%s\",\"returnByValue\":true}", esc);
            rc = gmb_cdp_command(cdp, "Runtime.evaluate", body, &out);
            char* val = rc == 0 && out ? gmb_cdp_evaluate_value(out) : NULL;
            snprintf(out_obs, cap, "{\"obs\":\"%s\"}", val ? val : (gmb_cdp_last_error(cdp) ? gmb_cdp_last_error(cdp) : "err"));
            if (val) free(val);
        } else if (strncmp(verb, "snapshot", 8) == 0) {
            gmb_cdp_command(cdp, "DOM.enable", "", NULL);
            rc = gmb_cdp_command(cdp, "DOM.getDocument", "{\"depth\":-1,\"pierce\":true}", &out);
            snprintf(out_obs, cap, "{\"obs\":\"%s\"}", rc == 0 && out ? out : "no dom");
        } else {
            snprintf(out_obs, cap, "{\"obs\":\"tool browser non supportato: %s\"}", verb);
            if (out) free(out);
            return -1;
        }
        if (out) free(out);
        return rc == 0 ? 0 : -1;
    }
    snprintf(out_obs, cap, "{\"obs\":\"tool sconosciuto: %s\"}", tool);
    return -1;
}
/* gmb_agent_loop.c — implementazione del loop Brain→Azione.
 * Ogni step: brain(transcript) → se risponde con un AgentAction JSON viene eseguita
 * (gmb_agent_action_run) e l'osservazione torna nel transcript; se risponde con testo
 * libero (nessuna azione) è la risposta finale e il loop termina. Policy capability
 * applicata sul nome tool prima dell'esecuzione. */
#include "gmb_agent_loop.h"

/* brain GMBasic registrato dall'host/embedding (mai un server esterno di default) */
static gmb_brain_fn g_brain = NULL;
static void* g_brain_ctx = NULL;

int gmb_agent_brain_register(gmb_brain_fn brain, void* ctx) {
    if (!brain) return -1;
    g_brain = brain;
    g_brain_ctx = ctx;
    return 0;
}
void gmb_agent_brain_clear(void) { g_brain = NULL; g_brain_ctx = NULL; }
int gmb_agent_brain_is_set(void) { return g_brain != NULL; }

/* Ask one-shot al brain registrato (testo libero, per CodeGen/UX): invoca g_brain una volta
   con `prompt` e riempie out. Se nessun brain e' registrato ne' MLX configurato -> errore
   esplicito (mai no-op). Ritorna 0 ok. */
int gmb_brain_ask_sync(const char* prompt, char* out, size_t cap) {
    if (!out || cap == 0) return -1;
    out[0] = 0;
    if (!prompt) { snprintf(out, cap, "error: prompt vuoto"); return -1; }
    if (g_brain)
        return g_brain(g_brain_ctx, prompt, out, cap);
    const char* mdir = getenv("GMB_MLX_MODEL_DIR");
    if (mdir && *mdir) {
        if (gmb_brain_mlx_auto(mdir, out, cap) != 0)
            return -1;
        return g_brain ? g_brain(g_brain_ctx, prompt, out, cap) : -1;
    }
    snprintf(out, cap,
        "error: nessun brain registrato — GMB_MLX_MODEL_DIR o gmb_agent_brain_register / GMB_BRAIN_URL.");
    return -1;
}

static void logf(char* log, size_t cap, const char* fmt, ...) {
    size_t p = strlen(log);
    if (p + 16 >= cap) return;
    va_list ap;
    va_start(ap, fmt);
    vsnprintf(log + p, cap - p, fmt, ap);
    va_end(ap);
}

/* estrae il nome tool (chiave "tool"/"name") dal JSON della risposta per la policy */
static void extract_tool_name(const char* reply, char* out, size_t cap) {
    out[0] = 0;
    const char* key = strstr(reply, "\"tool\"");
    if (!key) key = strstr(reply, "\"name\"");
    if (!key) return;
    const char* colon = strchr(key, ':');
    if (!colon) return;
    const char* v = colon + 1;
    while (*v && (*v == ' ' || *v == '"')) v++;
    const char* s = v;
    while (*v && *v != '"') v++;
    size_t n = (size_t)(v - s);
    if (n >= cap) n = cap - 1;
    memcpy(out, s, n);
    out[n] = 0;
}

static void trans_add(char* t, size_t tcap, int* tlen, const char* fmt, const char* arg) {
    size_t cur = (size_t)(*tlen);
    if (cur >= tcap) return;
    int w;
    if (arg)
        w = snprintf(t + cur, tcap - cur, fmt, arg);
    else
        w = snprintf(t + cur, tcap - cur, "%s", fmt);
    if (w > 0) *tlen += w;
}

int gmb_agent_loop_run(gmb_brain_fn brain, void* ctx, const char* agent, const char* goal,
                       int max_steps, char* log, size_t logcap) {
    if (!brain || !log || logcap == 0) return -1;
    log[0] = 0;
    char transcript[32768];
    /* Modalità brain (TOOL|COMPUTER|CODE): GMB_AGENT_MODE o default TOOL.
       TOOL = azioni su tool (browser/computer/ui/files); COMPUTER = solo computer/ui;
       CODE = rispondere con un programma GMBASIC come testo. */
    const char* mode = getenv("GMB_AGENT_MODE");
    if (!mode || !*mode) mode = "TOOL";
    const char* mode_rule =
        (strcasecmp(mode, "COMPUTER") == 0) ?
            "Usa SOLO azioni COMPUTER/UI (coordinate o testi UI). Mai tool browser per il compito."
        : (strcasecmp(mode, "CODE") == 0) ?
            "Rispondi SOLO con un programma GMBASIC (codice BASIC, no JSON action)."
        : "Puoi usare azioni tool (browser/computer/ui).";
    int tlen = snprintf(transcript, sizeof(transcript),
        "Compito: %s\n\nMODALITA': %s\nRegola: %s\n"
        "Rispondi SEMPRE o con un'azione {\"action\":{\"tool\":\"...\",\"args\":{...}}}, "
        "oppure con la risposta finale in testo libero.\n\nStorico:\n",
        goal ? goal : "", mode, mode_rule);
    if (tlen < 0) return -1;

    for (int step = 1; step <= max_steps; step++) {
        char reply[8192];
        if (brain(ctx, transcript, reply, sizeof(reply)) != 0) {
            logf(log, logcap, "[step %d] brain errore\n", step);
            return -1;
        }
        if (!reply[0]) break;

        /* transcript limitato: quando quasi pieno compatta tenendo la coda */
        size_t tcur = strlen(transcript);
        if (tcur + strlen(reply) + 600 >= sizeof(transcript)) {
            size_t keep = 16384;
            size_t from = tcur > keep ? tcur - keep : 0;
            memmove(transcript, transcript + from, tcur - from + 1);
            tlen = (int)strlen(transcript);
        }
        trans_add(transcript, sizeof(transcript), &tlen, "assistant: %s\n", reply);

        /* MODALITA' CODE: il brain ha risposto con un programma GMBASIC → eseguilo
           con gmb_code_exec (mondo C) e riporta l'output come risposta finale. */
        if (strcasecmp(mode, "CODE") == 0) {
            /* estrai un eventuale blocco fenced (```basic ... ``` / ``` ... ```) */
            char prog[16384];
            const char* fb = strstr(reply, "```");
            if (fb) {
                const char* f0 = fb + 3;
                const char* nl0 = strchr(f0, '\n');
                const char* start = nl0 ? nl0 + 1 : f0;
                const char* fe = strstr(start, "```");
                size_t n = fe ? (size_t)(fe - start) : strlen(start);
                if (n >= sizeof(prog)) n = sizeof(prog) - 1;
                memcpy(prog, start, n); prog[n] = 0;
            } else { snprintf(prog, sizeof(prog), "%s", reply); }
            char exec_out[16384] = "";

                logf(log, logcap, "[step %d] CODE eseguito: %s\n", step, exec_out[0] ? exec_out : "(nessun output)");
                return 0;

            return -1;
